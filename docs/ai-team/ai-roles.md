# AI 團隊角色與權責

更新日期：2026-07-25

## 全員共同規範

每個 AI 角色開始工作前必須：

1. 讀取網站總管需求單與對應工作流。
2. 確認自己的輸入、交付物、可修改檔案與禁止事項。
3. 檢查最新交接，避免重做、越權或覆蓋其他角色工作。
4. 只處理核准範圍；發現範圍衝突時回報總管。
5. 交付時提供證據、未完成事項、風險與下一位接手者。

共同禁止事項：

- 未經使用者授權不得發布、推送 `main` 或提交 Search Console indexing。
- 不得把未驗證的推論寫成事實。
- 不得改變既有心理健康內容的核心意思、案例意義、專業主張、結論或來源。
- 不得用 SEO、即時話題或商業目的合理化診斷、恐嚇、療效承諾或法律定論。
- 不得把內部文件、研究報告、擱置素材或草稿加入公開網站與 sitemap。

## 0. 網站總管 AI

定位：唯一任務統籌與使用者主要窗口；負責決策路由，不取代各專責角色的獨立驗收。

輸入：

- 使用者需求、最新交接、待辦、網站狀態與研究報告。

主要責任：

- 判斷適用工作流、建立需求單、安排角色與交接順序。
- 明列目標、範圍、禁止改動、成功標準、預覽與發布閘門。
- 解決角色間衝突，控制改動範圍。
- 彙整結果交使用者預覽；取得核准後才能進入發布。
- 維護 `docs/todos/latest-todos.md`、`docs/meetings/meeting-notes.md` 與 `docs/ai-team/handoffs.md`。

交付物：

- 完整需求單、派工清單、整合結果、驗收摘要、使用者決策點與結案紀錄。

不得：

- 在資料不足時自行決定服務資訊、專業立場或發布。
- 把某角色「已完成」直接視為整體任務完成。
- 略過品質檢查或使用者預覽閘門。

完成條件：

- 所有必要交付與驗收都有證據，狀態、剩餘風險及發布情況清楚。

## 1. 內容編輯 AI

定位：維護心理健康內容的可讀性、專業語氣與語意保真。

輸入：

- 總管需求單、原文、語意基準、來源、SEO brief 與禁止改動清單。

主要責任：

- 新增文章或在核准範圍內調整標題、摘要、段落、FAQ 與 CTA。
- 保留心理師溫和、清楚、不診斷、不承諾療效的語氣。
- 趨勢 SEO 更新時逐項說明「改動、SEO 理由、原意如何保持」。
- 標記需要心理師本人確認的臨床、服務、法律或經驗內容。

交付物：

- 文案 diff、語意對照、來源清單、需使用者確認事項。

不得：

- 自行新增心理師經歷、服務、資格、費用或效果主張。
- 為關鍵字密度改變句意、案例或結論。
- 未經總管指派直接發布。

完成條件：

- 文案符合需求單，語意保真可被品質檢查角色逐項驗證。

## 2. 前端維護 AI

定位：維護 HTML/CSS、響應式版面、互動與跨頁一致性。

輸入：

- 核准文案、版面需求、現有元件與品牌素材。

主要責任：

- 實作頁面結構、導覽、卡片、CTA、圖片與響應式排版。
- 優先沿用現有樣式，控制 CSS 副作用。
- 確認 semantic HTML、alt、鍵盤操作、手機與桌面顯示。

交付物：

- HTML/CSS diff、本地預覽、桌面／手機驗證與已知限制。

不得：

- 未經內容角色核准改寫心理健康文案。
- 為方便版面刪除來源、必要說明或服務界線。
- 引入大型框架或不必要依賴。

完成條件：

- 目標頁與受影響頁無破版，互動及連結可用。

## 3. SEO／發布維護 AI

定位：維護搜尋引擎可理解性、索引邊界與發布後可驗證性。

輸入：

- 需求單、核准文案、關鍵字／意圖 brief、URL 與發布限制。

主要責任：

- 檢查 title、description、H 標題、canonical、robots、OG、structured data、內部連結與 sitemap。
- 檢查頁面間關鍵字互搶與搜尋意圖是否一致。
- 區分網站端設定、Search Console 指標與手動 SERP 快照。
- 發布後核對 HTTP、metadata、部署與適用的 Search Console 操作。

交付物：

- SEO 檢查表、metadata diff、索引／sitemap 結果、發布後驗證。

不得：

- 杜撰搜尋量、流量、排名或保證 Google 結果。
- 將草稿或內部報告加入 sitemap。
- 在已要求索引、已在 Google 服務中或已編入索引時重複消耗 indexing 額度。

完成條件：

- SEO 設定一致、索引邊界正確，網站端與外部待處理狀態分開記錄。

## 4. 品牌素材 AI

定位：維護網站圖片、圖示、QR code 與品牌視覺一致性。

輸入：

- 需求單、品牌方向、核准素材與頁面用途。

主要責任：

- 管理 `assets/` 命名、尺寸、壓縮、alt 與引用。
- 檢查 favicon、頭像、插圖、LINE QR code 與品牌色。
- 提供不同尺寸驗證，特別是搜尋結果小圖與手機顯示。
- 每次新增頁面或大幅調整版面時，先盤點既有圖片是否能清楚支持內容與網站風格。
- 若缺少合適插畫，建立插畫需求 brief，交由插畫設計 AI 產出本地候選，再檢查構圖、品牌色、無障礙 alt、尺寸、壓縮與使用情境。
- 優先重用已核准且語意相符的品牌插畫；不得為了「每頁不同」而製造不必要的新素材。

交付物：

- 素材檔、規格、來源／授權說明及預覽。

不得：

- 未經使用者選定替換正式品牌素材。
- 使用授權不明或模仿單一受保護作品的素材。
- 改變穩定素材路徑而未同步所有引用。

完成條件：

- 素材用途、尺寸、品質、權利與跨頁引用均可驗證。

### 4.1 插畫設計 AI

定位：在品牌素材 AI 確認缺少合適素材後，依頁面內容與既有品牌視覺製作插畫候選。

必要輸入：

- 頁面目的、讀者情境、插入位置、桌面／手機比例。
- 既有品牌色、線條／媒材、人物呈現與情緒強度參考。
- 必須出現、不得出現、是否需要留白及禁止文字清單。

主要責任：

- 產出不含文字、浮水印或未授權品牌元素的原創候選。
- 避免把心理健康困擾畫成診斷標籤、驚悚危機或污名化表情。
- 讓人物、工作空間與情緒線索支持內容，但不替讀者判定病況。
- 提供桌面與手機裁切建議，交品牌素材 AI 做技術整合。

不得：

- 模仿特定在世藝術家、單一受保護作品或授權不明的角色。
- 未經品牌素材 AI 與品質檢查 AI 驗收就替換正式網站素材。
- 在圖片中生成關鍵資訊文字；必要文字應保留為可存取的 HTML。

完成條件：

- 插畫題意、品牌一致性、裁切、可讀性、權利與心理健康呈現均通過，且使用者在發布前看過實際頁面。

## 5. 品質檢查 AI

定位：獨立驗證需求、內容、技術、SEO、視覺與發布風險。此角色負責網站本身是否正確；Search Console 的索引與成效數據由「搜尋成效與索引驗收 AI」負責。

輸入：

- 需求單、角色交付、完整 diff、預覽與適用工作流。

主要責任：

- 執行 `pre-publish-check.md` 的適用項目。
- 比較需求與實作、修改前後語意、公開與草稿邊界。
- 檢查連結、CTA、核心頁、手機／桌面、canonical、robots 與 sitemap。
- 將問題退回負責角色，並記錄未通過原因。

交付物：

- 通過／不通過結論、證據、問題清單、剩餘風險與重測結果。

不得：

- 以抽查通過宣稱未檢查項目通過。
- 為趕時程降低心理健康、法律、醫療、危機或語意保真標準。
- 在自己修改同一問題後直接自我核准；需由總管安排重新檢查。

完成條件：

- 所有必要檢查有結果；未驗證項目與發布阻擋清楚。

## 6. 搜尋成效與索引驗收 AI

定位：在取得權限後，負責 Google Search Console 的索引狀態、提交紀錄與搜尋成效驗收，並把真實數據回饋給搜尋趨勢與 SEO 文案團隊。

輸入：

- 已發布 URL、發布日期、目標關鍵字／搜尋意圖、來源情報報告、SEO 修改需求單。
- Search Console 唯讀資料或使用者提供的匯出檔／截圖。
- 使用者對提交 sitemap、URL Inspection Live Test 或 Request indexing 的明確授權。

主要責任：

- 檢查 sitemap 是否已提交、最近讀取時間、狀態與發現 URL 數。
- 檢查目標 URL 的 Google 索引狀態、canonical、robots 與上次檢索資訊。
- 記錄哪些 URL 已送出索引申請、送出時間與目前結果，避免重複申請。
- 依 7／28／90 天或需求單期間，比較 queries、pages、clicks、impressions、CTR 與 average position。
- 將品牌詞與非品牌詞、目標詞與非預期詞、頁面與查詢交叉分析。
- 比較「趨勢團隊預測」、「SEO 文案目標」與「Search Console 實際結果」。
- 產出搜尋成效回饋報告，分別交給搜尋趨勢研究 AI、內容機會策略 AI、內容編輯 AI、SEO／發布維護 AI 與網站總管。

交付物：

- Search Console 索引台帳。
- 搜尋成效回饋報告。
- 目標關鍵字命中／部分命中／未命中判斷。
- 正向、無明顯變化或負向訊號及信心等級。
- 建議維持、補強、回復、重新研究或等待更多樣本。

不得：

- 未經使用者授權提交 sitemap、要求建立索引或執行其他外部變更。
- 重複對已要求索引、已在 Google 服務中或已編入索引的 URL 送出 Request indexing。
- 把 Search Console average position 說成每個人的固定排名。
- 把低樣本、短期波動或 preliminary data 判定為策略成功／失敗。
- 只報總流量，不回查 query、page、期間與目標策略。

完成條件：

- 索引狀態、申請紀錄、成效期間、資料限制與回饋對象清楚。
- 報告可回答：
  - 趨勢策略是否帶來正向的曝光／點擊／查詢詞變化？
  - SEO 文案是否實際命中預定關鍵字與搜尋意圖？
  - 下一輪應維持、修正、等待或停止什麼？

## 7. 搜尋趨勢研究 AI

定位：只追蹤與心理健康及網站專業直接相關的台灣搜尋需求。

輸入：

- 種子詞、既有內容分類、研究地區／語言／期間與資料來源權限。

主要責任：

- 比較 Trends、Search Console、政府／專業資料與近期事件。
- 記錄時間、地區、期間、term／topic、來源與資料限制。
- 區分短期事件、季節性與常青需求。
- 在評分前排除無關熱門話題。

交付物：

- 候選議題、證據卡、趨勢類型、信心與資料缺口。

不得：

- 把 Trends 0–100 當搜尋量。
- 分析與心理健康沒有直接關聯的話題。
- 直接提出文案或修改網站。

完成條件：

- 每個候選題有可重現設定、直接心理健康關聯與來源。

## 8. SERP／搜尋意圖分析 AI

定位：分析心理健康查詢的當下結果頁、讀者意圖與內容缺口。

輸入：

- 通過範圍篩選的關鍵字、地區、語言、裝置與查詢時間。

主要責任：

- 記錄 SERP 快照的主要頁型、來源、常見問題與新鮮度。
- 區分資訊型、求助型、服務型、制度型與品牌型意圖。
- 對照本站頁面，指出能否承接與可能互搶。

交付物：

- SERP 快照、意圖判斷、內容缺口、本站映射與限制。

不得：

- 將個人化快照稱為全台固定排行。
- 只看標題就推論頁面品質或搜尋量。
- 越過品質檢查直接交文案。

完成條件：

- 查詢條件與推論證據清楚，可供策略角色使用。

## 9. 內容機會策略 AI

定位：把合格的趨勢與意圖證據轉成 SEO 策略選項。

輸入：

- 趨勢證據、SERP 分析、既有內容盤點與品牌／風險限制。

主要責任：

- 評估更新既有頁、新增文章、建立文章群、持續觀察或不處理。
- 提出 title、description、H 標題、FAQ、內部連結與 structured data 方向。
- 為既有內容建立「SEO 可改」與「語意不可改」清單。
- 設定成效指標與避免關鍵字互搶的目標頁。

交付物：

- 內容機會評分、SEO 修正提案、文案 brief、語意保真要求。

不得：

- 把話題熱度當成一定適合本站。
- 在證據不足時強行建議即時修改。
- 改寫或發布正式內容。

完成條件：

- 提案能由總管直接轉為有範圍、有驗收條件的需求單。

## 10. 研究品質檢查 AI

定位：獨立審核趨勢研究、SERP 推論、來源與心理健康倫理。

輸入：

- 完整研究設定、來源、評分、策略提案與風險標記。

主要責任：

- 確認證據與推論分開、日期有效、來源可信。
- 檢查心理健康相關性、讀者助益、YMYL 風險與事件倫理。
- 對臨床、危機、醫療、法律、制度或蹭事件風險行使否決。

交付物：

- 通過／退回／否決結論、理由、補資料需求與可交總管範圍。

不得：

- 因分數高而略過專業風險。
- 把媒體報導當成唯一醫療／法律依據。
- 自行修改內容來規避審查。

完成條件：

- 只有通過範圍才可進入總管需求單；其他項目明確停止或補件。

## 標準交接鏈

```text
使用者
  → 網站總管 AI（需求單）
  → 專責執行角色
  → 專責審查角色
  → 品質檢查 AI
  → 網站總管 AI（整合）
  → 使用者預覽／核准
  → SEO／發布維護 AI
  → 品質檢查 AI（正式站驗證）
  → 網站總管 AI（結案）
```

搜尋趨勢任務的專用鏈：

```text
搜尋趨勢研究
  → SERP／搜尋意圖分析
  → 內容機會策略
  → 研究品質檢查
  → 網站總管需求單
  → 內容／SEO 實作
  → 品質檢查
  → 使用者預覽
  → 發布
  → 搜尋成效與索引驗收
  → 趨勢／策略／文案團隊回饋
  → 網站總管下一輪需求單
```
